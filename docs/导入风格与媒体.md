# 导入聊天记录、表达风格与媒体

## 从 Alpha 导出

可使用 [Alpha 官方发布页](https://github.com/xunchahaha/alpha-releases) 导出自己有权处理的微信会话。其官方 [导出接口说明](https://github.com/xunchahaha/alpha-releases/blob/main/docs/api/http-api.md) 列出了普通 `json` 和其他格式；本项目使用保留以下字段的普通 JSON，不需要开启 Alpha HTTP API。

1. 在 Alpha 中按其说明加载自己的微信记录，选中目标会话与时间范围。
2. 选择普通 JSON 导出。若需要发回历史图片、表情包，同时导出媒体。
3. 保留 `messages.json` 与 `media/` 的相对位置。移动时移动整个导出目录，避免只复制 JSON。
4. 在 AI语忆的 **人设 → 从聊天记录导入人设** 中填写本机 JSON 完整路径。

JSON 是可读取的导出资料，不是微信官方加密备份。本项目不直接解密微信数据库或官方备份；HTML、Excel、加密文件及其他工具的不同字段结构需要先转换。

## 网页导入

1. 点击 **读取参与者**，核对姓名、说话人标识与消息数。
2. 分别选择“模仿谁”和“哪一位是你”，两者不能相同。群聊中只导入你选定的两位参与者，其他人的话不会作为这两人的资料。
3. 确认人设姓名、对你的称呼、性别和关系；不知道的信息不要猜。
4. 只有你允许机器人回发原媒体时，才勾选“允许在你主动索要时发送记录中的图片、表情包”。默认不启用导入媒体发送，也不自动发普通照片。
5. 点击 **导入为新人设**，完成后查看该人设，并点击 **保存并设为默认**。

导入每次创建新的人设 ID，不覆盖已有角色。原始 JSON 和媒体不变。处理上限为单个 200MB JSON；大文件可按时间分段预处理为一个符合字段约定的文件。

## 支持的数据结构

支持顶层消息数组，或 `{"messages":[...]}`。消息字段示例（全部为虚构数据）：

```json
{
  "messages": [
    {"id":"demo-1","sender_id":"demo-owner","sender_name":"体验者","kind":"text","text":"你记得那次看展吗","sent_at":"2026-06-01T20:00:00+08:00"},
    {"id":"demo-2","sender_id":"demo-role","sender_name":"林慕婉","kind":"text","text":"记得呀，那幅紫色的画好漂亮","sent_at":"2026-06-01T20:01:00+08:00"},
    {"id":"demo-3","sender_id":"demo-role","sender_name":"林慕婉","kind":"image","sent_at":"2026-06-01T20:02:00+08:00","refs":[{"kind":"image","uri":"media/demo.png"}]}
  ]
}
```

- `sender_id` 用来区分说话人；昵称可能重复，不能只靠昵称判断。
- `kind` 为 `text` 的 `text` 参与风格与回忆索引；语音只有已有文字转写且没有待复核标记时参与。
- 时间用 `sent_at` 的 ISO 格式，或 `sent_at_unix_ms` 毫秒时间戳。没有可靠时间的记录不应被当作精确日期证据。
- 图片/表情通过 `refs` 的 `kind: image/emoji` 与 `uri: media/...` 引用。只支持实际存在的 PNG、JPEG、GIF、WebP，单项不超过25MB。缺失或损坏媒体不会变成可发素材。

## “学习”是怎样发生的

导入后会在本机建立带日期、说话人和来源 ID 的 SQLite 检索索引，提取问答范例，统计导出时间范围最近两年的表达特点。每次回复只取相关回忆和范例，结合当前人设资料送给模型。

这不是模型微调。没有检索到可靠记录时应说明不确定；风格近似程度取决于数据质量和模型，不能据此认为模型等同于现实中的人。新 AI 对话与历史导出使用不同来源，避免把生成内容当成现实人物经历。

## 图片和表情包

默认林慕婉可使用内置表情。导入媒体开启后，可尝试“发个表情包”“发张看展的图”；图片须与记录中的上下文匹配。媒体索引默认不自动给私人照片做人脸身份判断，也不会自动发送普通照片。

发送使用原媒体文件，因此请保留原导出目录。GIF 能否在接收端以动态效果显示由微信与媒体格式共同决定。这里是回发已有素材，不是根据聊天新生成图片。

收到图片的识别由所选视觉模型完成；只导入文字资料不会自动获得视觉模型能力。

## 资料保存在什么地方

新角色资料位于本机 `private/<人设ID>/`，包括人设说明、档案、表达范例、记忆索引和媒体目录。主账号可以使用，朋友默认不能访问。软件内新对话的记忆编辑器只显示新对话与手工补充，导入原文不在其中编辑。

不要提交 `private/`、导出文件、运行日志、数据库、截图或备份到 GitHub。若要反馈问题，请用全新虚构记录复现。模型调用时，检索出的相关片段会发送到你配置的模型服务；导入操作本身在本机进行，不会自动向模型批量上传整份导出。
