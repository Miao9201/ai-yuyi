# 开发、测试与 Windows 构建

## 源码启动

需要 Windows x64、Python 3.12 x64、Node.js 22 或更高版本，以及下载依赖的网络。桌面界面使用 WebView2；系统已有组件时直接复用，缺少时由完整包中的微软签名安装程序准备。

```powershell
python -m pip install -r requirements.txt
powershell -NoProfile -ExecutionPolicy Bypass -File build-launcher.ps1
.\START.cmd
```

程序优先使用安装包内置运行环境；源码运行时回退到系统 Python/Node。源码副本只提供空白默认配置和林慕婉，没有模型密钥、微信授权或导入的人设。不要把自己运行后产生的数据再次提交。

## 本地验证

```powershell
python -m unittest test_import_persona
```

此测试使用临时目录与虚构聊天、现场生成的示例图片，检查说话人选择、回忆检索、风格范例、媒体许可、跨角色隔离、原文件不变及拒绝覆盖。不会调用真实模型或微信接口。

## 构建

构建只复制审核清单列出的文件，排除私人资料、日志和旧运行环境。修改源码后，先审核再更新清单：

```powershell
python packaging/review_source.py --update-manifest
powershell -NoProfile -ExecutionPolicy Bypass -File packaging/build-portable.ps1 -SourceRoot . -OutputRoot dist
```

构建脚本下载官方 Python 嵌入运行环境，安装固定版本依赖，复制本机 Node 可执行文件并保留其许可，随后准备校验过的微软 WebView2 SDK、保留其许可并验证运行组件安装程序的微软签名，再编译桌面窗口、便携包与自解压安装器。`dist/` 必须为空目录；不会自动删除旧构建。推荐在干净目录或 GitHub Actions Windows 环境构建。

本项目的 Windows 构建工作流会设置 Python 3.12、Node 22。手动运行 workflow 后下载构建产物即可；构建成功不等于已在所有 Windows 版本、所有微信账号上验证。

## 发布前检查

- 只提交源文件、公开默认人设和明确标注的虚构示例。
- 不提交 `private/`、运行中的 `data/`、微信导出、API Key、授权、数据库、日志、缓存、截图或备份。
- 默认模板位于 `templates/`。源码提供的少量默认 `data` 配置仅为新安装初始化，不允许用自己的运行配置替换它们。
- 对源码 ZIP、安装器、便携包分别检查文件内容、来源清单和 SHA-256；依赖命令行启动器可能写入构建机路径，发布构建会排除这些非必要启动器。
- `packaging/review_source.py` 只是辅助检查，不能证明任意私密文本已全部发现。发布者仍须人工复核，尤其是图片、导入资料和新增演示内容。
- 保留第三方许可与必要来源声明。不要用本项目的 MIT 文件替换第三方限制。

## 命令行导入

也可以使用相同导入器，无需网页：

```powershell
python import_persona.py analyze --source "<本机导出JSON路径>"
python import_persona.py import --source "<本机导出JSON路径>" --target "<模仿对象sender_id>" --self "<自己的sender_id>" --name "<人设名称>" --address "<对你的称呼>"
```

只有明确允许回发导入媒体时才增加 `--allow-media`。安装/便携版可用 `runtime\python\python.exe` 代替 `python`。导入文件与生成的私人人设不属于公开源码，不要提交它们。
